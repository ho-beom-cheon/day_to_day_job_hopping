# 운영 과정 v1 원고 작업실

상태: **편집 초안**. 이 디렉터리는 Flyway migration도 자동 seed도 아니며, 현재 DB에 적재되지 않는다. `dev-seed`의 6학습일 예시와 분리한다.

## 대상과 편집 기준

- 대상: **8년차 SI 개발자**. Java/Spring 실무 경험을 전제로 하되, 중요한 기본기는 요구사항 변경·기존 코드 수정·데이터 오류·연계 실패·회귀 테스트 상황에서 다시 확인한다. 특정 업종 경험은 전제하지 않는다.
- 구조: 6개월, 26교육 주차, 주 5학습일, 총 130학습일을 기본 편성으로 잡는다. 하루 목표는 **90~120분**이며, 실제 달력 날짜는 사용자의 시작일과 휴식 정책으로 배정한다.
- 한 학습일에는 목표, 설명, 실무 예시, 코드 또는 설계 과제, 확인 문제와 해설을 둔다. 문제는 앱의 개인별 AI 생성 결과가 아니라 발행 전 검수하는 공통 콘텐츠다.
- 확인 문제는 용어 정의나 단일 API 반환값 암기를 묻지 않는다. 선행 개념을 짧게 설명한 뒤 코드·로그·데이터·제약을 제시하고, 원인 분석이나 수정안의 선택과 그 근거를 묻는다. 오답도 실제로 선택할 법한 대응이어야 한다.
- 난이도 3은 기본 개념이 깨지는 경계 조건을 적용하고, 4는 수정 원인과 대안을 비교하며, 5는 화면·API·DB·배치 등 여러 계층에 걸친 변경의 영향과 테스트를 판단한다. 기본기를 빼지 않고 문제의 판단 수준을 올린다.
- 인프라 구축, 분산 시스템 내부 구조, 성능 이론은 해당 학습 주제를 이해하는 데 필요한 범위에서만 다룬다. 주된 과제는 업무 규칙 구현과 유지보수의 정확성이다.
- 시험 빈도: 사용자가 2026-09-23에 **일간 매 학습일·주간 매주·월간 매월·최종 1회**를 선택했다. 문항 수·시간·합격선은 아래 첫 주 편성에서 시험할 편집 기본값이며 아직 운영 정책으로 확정하지 않았다.
- 원문을 베끼지 않고 자체 설명·예제로 작성한다. 각 원고에는 공식 기술 문서의 URL을 출처로 남기고, 게시 전 정확성·권리·난이도를 사람이 검토한다.
- 본문과 문제의 정답을 검수한 뒤 DRAFT로 적재한다. 콘텐츠·문제·시험을 먼저 발행하고 마지막에 과정 버전을 발행한다. 발행 후에는 같은 버전을 수정하지 않는다.

## 현재 산출물

- [26주 편성 초안](course-outline.md): 130개 학습일의 주제와 순서. 제목과 범위의 편집 초안이며, 본문 완성이나 발행 승인을 뜻하지 않는다.
- [1주차 원고·문항](week-01.json): 5개 학습 본문과 5개 기본 문제의 구조화 초안. 학습 UI 적재 전 정답 및 표현 검토 대상이다.
- [1주차 평가 편성](week-01-assessment.json): 일간 시험 5개와 주간 시험 1개의 편집 초안. 같은 문제의 재출제를 허용하되 실전 평가 품질은 별도 검토한다.
- [1주차 검수 기록](week-01-review.md): 구조·기술 대조 결과와 발행 전 남은 품질 항목.

## 발행 전에 필요한 작업

1. 시험 문항 수·제한 시간·합격 기준을 확정한다. 26주/130일은 주 5일 가정의 편성 기준이며, 90~120분의 학습·시험 시간을 서비스의 `estimated_minutes`에 반영해야 한다.
2. 2~26주차의 본문·문항을 같은 수준으로 작성하고 각 출처를 검증한다.
   기존 1주차 초안과 별도 Java 4주 과정의 암기형 문제도 8년차 대상 기준으로 다시 검수하고 새 버전으로 작성한다. 이미 발행된 버전은 직접 수정하지 않는다.
3. 일간·주간·월간·최종 시험의 문항 중복 정책과 배점·재응시 정책을 결정한다.
4. 원고 스키마 검사와 정답 검사, 전문 검수, PostgreSQL DRAFT 적재, `catalog-ops validate`, 브라우저 확인을 거친 뒤 발행한다.

현재 공개 작성·발행 API는 없다. 적재는 별도 운영 도구 또는 검토한 SQL이 필요하며, 운영 DB에 개발용 Flyway seed를 적용해서는 안 된다.
