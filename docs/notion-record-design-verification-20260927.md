# Notion 학습 기록 디자인 개선

관련 이슈: [#8 외부 연동 완성](https://github.com/ho-beom-cheon/day_to_day_job_hopping/issues/8)

## 변경

- `NotionPageTemplate`: 본문 전체를 감싸던 파란 callout을 일반 문단으로 교체했다. 제목·날짜는 회색 보조 텍스트, 문제·답안 확인·피드백은 기본 제목과 구분선으로 구성한다.
- 보기의 중복 글머리표를 제거하고 내 답·정답·채점은 라벨만 굵게 표시한다. 사용자 후속 요청에 따라 문제(🧩), 답안 확인(✍️), 해설·피드백(💡), 학습 자료(📖), 메모(📝), 오답 분석(🔎), 주간·월간 리포트(📅·📊), 완료·다음 학습(✅·➡️)의 주요 제목에만 이모지를 사용한다. 일반 라벨·보기·본문에는 장식 이모지를 넣지 않는다. 채점 결과만 빨강·초록 글자색을 사용하며 배경색은 사용하지 않는다.
- `HttpNotionProvider`: 기존 callout과 구형 문단을 앱 소유 블록으로 인식하고 새 문단 구조로 교체한다. 새 본문을 먼저 추가한 뒤 이전 앱 본문을 휴지통 처리하며 별도의 개인 메모 블록은 보존한다. 같은 버전의 새 본문은 반복 생성하지 않는다.
- `NotionSnapshotFactory`: 형식 버전을 올려 기존 기록도 다음 수동 동기화 때 갱신되게 했다. 이모지 조정 후에도 새 버전으로 기존 페이지를 갱신한다.

### 학습 자료 콜아웃과 코드 블록 후속 반영

- `📖 학습 자료`는 기본 제목 서식을 사용하고, 자료의 소제목·내용만 회색 💡 callout으로 묶었다. 제목의 파란 배경은 사용자 후속 요청에 따라 제거했다.
- `NotionMarkdown`은 CommonMark 0.30.0으로 Markdown을 해석한다. 6종 기록의 지문·보기·내 답·정답·해설·메모·분석 등에서 fenced/indented code를 Notion의 실제 `code` 블록(`/코드`)으로 저장한다. 언어 별칭을 정규화하고 알 수 없는 언어는 plain text로 저장한다.
- 코드 안의 빈 줄, 들여쓰기, 문자열의 리터럴 `\n\n`, 한글·이모지를 보존한다. 코드에 `정답` 같은 구획 이름이 있어도 기록 구획으로 분리하지 않는다. 보기 번호가 코드 fence 앞에 붙어 코드 해석을 막지 않도록 스냅샷 생성도 조정했다.
- 본문 속 짧은 백틱 표현은 인라인 코드로 변환한다. 학습 자료 callout 안에도 코드 블록을 넣을 수 있다. 제목의 기본 서식을 기존 기록에 다시 반영하기 위해 형식 revision을 `7_000_000_000_000_000`으로 올렸다.
- 원본에서 코드 fence 또는 들여쓰기로 구분된 코드를 변환한다. 일반 문장에 섞인 소스처럼 Markdown 구분이 없는 내용은 임의로 코드라고 추정하지 않는다.

## 모바일 화면 후속 조정 (2026-09-27 03:59 KST)

- 학습 자료의 회색 💡 callout을 제거했다. `📖 학습 자료`와 자료 소제목은 기본 제목, 설명은 일반 문단, 코드는 기존 Notion 코드 블록으로 출력한다. 기존 문제·시험·오답·리포트 템플릿은 건드리지 않았다.
- 학습 결과에만 형식 revision `1_000_000_000_000`을 추가해 다음 앱 동기화에서 새 형식으로 갱신되게 했다. 현재 선택된 과정이 기존 두 학습 기록을 만든 과정과 달라 앱 batch #11은 대상 0건이었다. 따라서 기존 노션 학습 페이지 2건의 callout만 Notion 커넥터로 교체했다. 두 페이지를 다시 읽어 `## 📖 학습 자료` 아래 `###` 소제목과 일반 문단이 있고 callout이 없으며 나머지 본문이 유지됨을 확인했다.
- 배포 중 이미 적용된 Flyway V24 파일의 문구 변경으로 checksum 검증이 실패했다. 적용 당시 V24 문구를 복원하고 수정된 설명은 새 V26으로 옮겼다. V24·V25·V26 적용 성공을 DB에서 확인했다.
- 백엔드 빌드의 테스트 115개가 통과했고, 네 서비스 모두 running/healthy이며 로컬 `/login`은 HTTP 200이다. 노션 저장 블록을 확인했으며 모바일 시각 검증은 사용자 제공 피드백과 블록 구조에 근거한다.
