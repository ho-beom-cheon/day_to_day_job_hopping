# 작업 10 로그인·온보딩 UI 계약 대조

## 적용 기준

- 로그인 시작은 AJAX가 아닌 브라우저 최상위 이동 `GET /oauth2/authorization/google`을 사용한다.
- Backend 고정 실패 경로 `/login?error=LOGIN_FAILED|ACCOUNT_NOT_ALLOWED`만 해석하고 공급자 예외·토큰을 화면에 노출하지 않는다.
- 화면 진입 시 작업 9의 CSRF → 현재 사용자 복원 순서를 재사용한다. 미로그인은 Google 로그인, 과정이 없는 사용자는 `/onboarding`, 과정이 있는 사용자는 `/workspace`로 이어진다.
- 템플릿 조회는 `TEMPLATE-001`, 최초 배정은 `CURR-008`을 사용한다. 조회 중 콘텐츠나 임시 템플릿을 생성하지 않는다.
- 과정·템플릿 ID는 JavaScript number로 변환하지 않고 문자열로 유지한다. revision과 집계 수치는 number로 구분한다.
- 최초 배정은 `startDate`, `dailyStudyMinutes`, `restDaysPerWeek`, `restWeekdays`를 전송한다. 시작일은 Asia/Seoul 오늘부터 90일 안, 휴식 요일은 중복 없는 0–6개로 제한한다.
- 동일 논리 요청의 payload와 UUID Idempotency-Key를 오류 후 재시도에도 재사용하며, CSRF는 작업 9 client가 세션 토큰을 전송한다.

## 화면 상태

| 상태 | 사용자 표현 / 동작 |
|---|---|
| 익명 | Google 로그인 시작 버튼과 허용 계정 안내 |
| 로그인 거부 | 허용 계정 확인 안내, 재시도·처음 화면 동작 |
| 일반 로그인 실패 | 인증 취소·만료 가능성 안내, 재시도 |
| 세션 만료 | 온보딩 입력 대신 다시 로그인 동작 |
| 로그인 + 현재 과정 있음 | `/workspace` 복원 |
| 로그인 + 현재 과정 없음 | 발행 템플릿과 일정 정책 입력 |
| 템플릿 loading/error/empty | 진행, 재조회, 운영 콘텐츠 미배포를 각각 구분 |
| 배정 처리/실패 | 중복 클릭 차단, 계약 오류별 안내, 같은 요청 재시도 |
| 배정 성공 | 사용자 캐시를 갱신하고 `/workspace` 이동 |

## 의도적으로 제외한 범위

- 학습 콘텐츠·템플릿 적재는 운영 절차의 책임이며 UI가 대신 생성하지 않는다.
- 로그아웃은 CSRF 보호 POST 계약이므로 이번 헤더에 동작하지 않는 링크를 만들지 않았다. 설정 UI 단계에서 연결한다.
- 대시보드·로드맵·문제 화면의 데이터·내비게이션은 작업 11–13 범위로 유지한다.
