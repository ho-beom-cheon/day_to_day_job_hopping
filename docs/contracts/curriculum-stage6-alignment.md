# 작업 6 커리큘럼·학습 채택 기준

관련 [이슈 #5](https://github.com/ho-beom-cheon/day_to_day_job_hopping/issues/5). 원본 OpenAPI v1.2.1 및 V2 DB 기준선과 대조했다. 실제 운영 콘텐츠는 적재하지 않고 테스트 전용 콘텐츠를 사용한다는 사용자 결정을 따른다.

| 차이 | 채택 기준 |
|---|---|
| templateId / templateVersion | templateId는 curriculum_version.id, 표시 버전과 제목은 발행 메타데이터에 보관한다. 배정 후 버전을 교체하지 않는다. |
| API Session / DB learning_session | API sessionId는 learning_day_item.id다. DB learning_session은 시간 측정용이므로 자기보고 분을 그 active_seconds로 위장하지 않는다. 전용 확장 행에 자기보고 분을 보관한다. |
| 월차·주차·학습일 | 월차/주차는 교육 모듈이다. DAY 메타데이터에 고정 dayNo/monthNo/weekNo를 보관하여 교육 주차의 월차 경계를 표현한다. 날짜는 배정 후 learning_day에서 조회한다. |
| 콘텐츠 목록·완료 | ITEM과 불변 콘텐츠 버전의 편성을 별도 관계로 저장한다. 사용자·세션별 콘텐츠 인스턴스 ID와 완료시각을 새로 배정하고 복합 소유권 FK로 연결한다. |
| 필수 확인 문제 | 콘텐츠 버전과 문제 버전의 관계를 저장한다. 현재 사용자·과정의 SUBMITTED 이력이 모든 문제에 존재해야 한다. 정답률은 요구하지 않는다. 문제 제출 API는 8번이다. |
| 시험 | 발행된 시험 버전과 문항을 배정 전에 검증하고 같은 배정 트랜잭션에서 시험 항목을 고정한다. 응시·제출·채점은 9번이다. |
| 현재 과정 | 진행 과정 1개를 유지하며, 없으면 마지막 완료 과정을 반환한다. 완료 후 새 과정 생성 시 이전 과정·콘텐츠·완료 기록을 보존한다. |
| 진척 | 고정된 필수 세션 수를 분모로 조회 집계한다. 완료 중복으로 카운터를 더하지 않는다. 0 분모는 null. 1자리 소수 반올림을 사용한다. |
| 불변성 | 발행한 템플릿 구성과 콘텐츠 본문/메타데이터 변경·삭제를 DB에서도 차단한다. 폐기는 새 배정만 막고 기존 배정 버전 조회는 보존한다. |
| 동시성 | 사용자 행 → 과정 행 순서로 잠근다. 생성/세션 완료의 재현은 기존 IdempotencyService를 사용하며 재현 전 현재 사용자와 소유권을 검증한다. 시작·완료는 scheduleRevision을 증가시키고 반복 요청은 기존 시각과 값을 보존한다. |
| 초기 운영 | 검토한 DRAFT 콘텐츠와 전체 구성을 적재한 뒤 운영 검증 서비스로 발행한다. 목록 GET에서 생성하거나 적재하지 않는다. 배포된 템플릿이 없으면 빈 배열을 반환한다. |

외부 발송 없이 업무 변경과 outbox 이벤트만 같은 트랜잭션에 저장한다. 휴식/일정 변경 API, 문제/시험 실행 API, 운영 콘텐츠 및 화면은 각 후속 범위다. 기존 V1–V4는 변경하지 않는다.
