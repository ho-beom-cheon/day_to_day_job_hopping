# 26주 통합 학습 설계 적용·검증 기록

> 이 문서는 17시대 설계 단계의 기록이다. 이후 실제 98개 원문 보강, 카탈로그 133개, 90/120분 세션, 실제 OpenAI 호출 검증은 [학습 원문 보강 검증](financial-topic-catalog-verification-20260927.md)에 기록했다. 아래의 35개 카탈로그/외부 호출 미실행 내용은 당시 상태이며 현재 QA 상태를 뜻하지 않는다.

## 직접 확인할 화면

[대표: 26주 학습 설계 QA](http://localhost:18081/learning/program) · [기존 추가 학습 QA](http://localhost:18081/learning/extra)

2026-09-27 17:37 KST 기준 QA 실행 중. 18081 포트는 127.0.0.1에만 바인딩되어 있다. 기존 QA 설정의 `과정 검증 사용자`가 자동 적용되므로 Google 로그인은 필요 없다. 새 화면에서 26주 목차와 일간·주간·월간·최종 시간 미리 보기를 확인했다. 실제 서술형 시험을 제공하는 화면은 아직 아니다.

재시작(프로젝트 루트, Docker Desktop·기존 QA 이미지/DB·추적 제외 `.env.course-qa.local` 필요):

```powershell
docker compose --env-file .env.course-qa.local -f compose.course-qa.yaml -f compose.study-program-qa.yaml up -d --no-build --wait
```

기존 운영 서비스는 계속 실행 중이다. 이번 코드로 운영 컨테이너를 교체하지 않았다. 따라서 운영 8080/공개 HTTPS에서 새 화면이 배포되었다고 주장하지 않는다. 기존 운영 시작 명령은 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\ide.ps1 -Action Up -Mode Public`이다.

## 구현한 범위

- 확정 결정: `docs/financial-backend-program-decisions.md`. 경력 사실/확장 학습, 시간, 평가, 재응시, 비용, 개인정보 정책을 기록했다.
- 실행 프롬프트 원본: `backend/src/main/resources/prompts/financial-backend-v1/`. 공통 1개 + 역할 11개, 스키마 4개, 26주/130일 **목표 목차**. 130개 학습 원문은 아니다.
- `StudyPolicy`: 교육 월 경계, 평가 우선순위, 시간 배분, 정규+추가 목표 합산/중복 제거, 초과 범위 명시, 최종 회차 분할.
- `StudyRequest`: typed 목표/원문으로 생성 입력 구성, 현재 서술형 답안만 채점에 포함. 생성 전 미검수/미발행 원문 차단.
- `StudyAssessment`: 문항·슬롯·근거 버전·정확 발췌·목표 커버리지·배점·중복 검증, 풀이용 응답에서 정답 제거, 객관식 규칙 점수, 서술형 부분 점수와 HOLD. 의미상 정답성·학습 효과가 검증되었다는 뜻은 아니다.
- 기존 AI 연습 경로: 공통 사실/경력 가드레일과 입력 허용 목록을 실제 worker/공급자 어댑터에 연결했다. 이전 문제 비교는 서버에만 남긴다.
- 기존 일간 피드백 경로: 원시 활동 이력 대신 서버가 선택한 주제만 전달한다. 개인 성취 추정 대신 학습 방향을 안내하고 응답의 과정 ID/날짜는 서버에서 복원한다.
- 신규 조회 API: `/api/v1/study-program`, `/api/v1/study-program/preview`. 인증 필요, 읽기 전용. 신규 STUDY_* 역할은 일반 생성 API에 개방하지 않았다.

## 검증 근거

- Docker의 JDK 21에서 `sh mvnw -B -ntp verify`: 백엔드 130 테스트 통과(실패/오류/skip 0). 개인정보 경계 및 성취 추정 차단 수정 후 17:45 KST 빌드로 갱신하고 QA 백엔드에 적용했다. PostgreSQL Testcontainers 전체 통합 테스트는 이번 변경에서 실행하지 않았다.
- 프런트 Docker 배포 빌드: typecheck, 전체 ESLint, 45 파일/184 테스트, Next.js production build 통과.
- QA 실데이터 조회: 26주/130일, `generationReady=false`, `OUTLINE_READY` 확인.
- 일간 30분: 학습 1,260초 + 평가/해설 540초.
- 주간 60분: 1,800초 + 1,800초.
- 월간 120분: 2,160초 + 5,040초.
- 최종 미리 보기 130 목표/30분 회차: 24,600초, 130 슬롯, 15회차. 목차에 대한 기본 추정이며 실제 최종 시험 문항 수 확정값이 아니다.
- 브라우저에서 월간 선택/최종 선택 전환, 390px viewport 확인. CSS 가용 너비와 scrollWidth 모두 375px로 수평 넘침 없음. 브라우저 console error/warn 0개.
- QA 교체 전후 행 수 동일: 학습 항목 50, 시험 응시 2, 문제 풀이 14. 이 비교는 행 내용 전체의 digest 검증을 의미하지 않는다. DB migration/삭제/재배정은 수행하지 않았다.
- 실제 OpenAI 유료 호출은 이번 검증에서 실행하지 않았다. 고정 사례의 서버 검증 통과와 실제 모델의 출제/채점 품질은 구별한다.
- 커밋·푸시·PR·원격 이슈 생성 없음. 기존 staged/unstaged/untracked 변경 보존.

## 요구사항별 남은 연결

| 결정 | 반영한 곳 | 실제 운영에서 남은 작업 |
| --- | --- | --- |
| OpenAI 재사용, 비용 직접 확인 | 기존 설정 유지, 프롬프트 어댑터 | 신규 역할별 실제 공급자 품질 검증 |
| 개인 기록은 DB 집계, 결과 조건만 전달 | 연습/피드백 전송 허용 목록, StudyRequest | DB 목표별 통계로 새 학습 목표/난이도 추천하는 어댑터 |
| 26주 혼합, GA/KDB/아리수/여신/알고리즘/AI | curriculum.json, 공통 규칙 | 목표별 본문·예제·실습 보강, 공식 근거 검수, 새 과정 버전 발행 |
| 30/60/90/120분 총시간 | StudyPolicy, 미리 보기 | 실제 학습 편성과 연결. 기존 추가 학습의 15/30/60분 UI/DB 계약 확장 |
| 세 가지 문제 유형, 직접 코드 작성 제외 | assessment.schema, 검증기 | 기존 객관식 시험 화면에 서술형 입력/자동 저장/제출 연결 |
| 모든 실제 학습 목표 평가 | scope/slot/evidence 검증 | 완료된 정규·추가 학습에서 불변 목표 목록을 만드는 DB 연결 |
| 일간30%, 주간50%, 월간70%와 대체 | StudyPolicy 및 테스트 | 새 버전 실제 달력 배정에 적용; 기존 발행 일정은 보존 |
| 추가 학습 세 모드·총합·앞당기기 | 프롬프트/정책, 기존 AHEAD 유지 | 추가 목표 평가와 주/월/최종 범위 귀속 연결 |
| 재응시는 동일 범위의 새 문제 | retake 프롬프트, 서버 중복 검증 | 새 문제 세트/응시/답안 저장·최초 기록 보존 연결 |
| 최종 여러 세션, 한 결과 | 회차 계산/합산 채점 규칙 | 세션별 생성·저장·이어 풀기·마감·전체 제출 연결 |
| 의미 기반 부분 점수, HOLD | grading 프롬프트, 점수 검증 | 비동기 채점 작업·결과 화면·사람 기준 답안 품질 검증 |
| 부족 분야 보강 | gap_audit/source_authoring/validation | 실제 원문 조사·작성·검수·발행 작업. QA 카탈로그 35개 원문 중 AI 분야 없음 |

전체 요구 구현이 끝났다는 완료 보고가 아니다. 위 연결이 끝나기 전에 신규 26주 과정을 활성화하거나 기존 시험을 교체하면 안 된다. 현재 접속 가능한 결과는 설계 미리 보기와 기존 학습이며, 신규 학습/시험은 위 후속 통합 후 제공해야 한다.
