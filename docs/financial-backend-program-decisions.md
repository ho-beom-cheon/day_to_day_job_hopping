# 금융권 백엔드 학습 설계 확정 기록

승인: 2026-09-27 대화. 이 문서는 이전 `CHATGPT_26_WEEK_CURRICULUM_BRIEF.md`와 상충하는 시간·평가·개인화 정책을 대체한다. 기존 발행 버전과 사용자 기록에는 소급 적용하지 않는다.

## 목표와 커리큘럼

6개월을 목표로 26 교육 주차, 주당 5 학습일의 큰 틀을 둔다. 실제 달력상 이수는 6개월을 넘을 수 있다. 26개의 고정 프롬프트를 만들지 않고 버전이 있는 공통 역할 프롬프트에 주차·학습 목표·원문·시간·난이도를 주입한다. Java/Spring, SQL/DB, 테스트, 알고리즘, 금융 업무, AI 개발 활용, 면접을 매주 섞는다. 하루 2~3분야도 허용하며 공통 상황이 도움이 될 때 연결한다. 서로 무관한 주제를 억지로 엮지 않는다.

금융권 백엔드 면접이 중심이다. 업무 지식은 개발 판단에 필요한 범위로 다루며 일반 투자/경제 과정으로 확대하지 않는다. 알고리즘은 자료구조, 접근법, 복잡도, 경계값, 주어진 코드/수정안/테스트의 분석을 포함한다. 직접 코드를 작성하는 평가는 요구하지 않는다. 분석형 평가만으로 코딩 테스트 구현 능력이 증명되었다고 표현하지 않는다.

## 경력 사실과 학습 확장

| 기준 | 사실로 사용할 범위 | 심화 학습 범위 및 주의 |
| --- | --- | --- |
| 라이나 손해보험 GA 채널 | 보험 설계사가 쓰는 채널 화면 유지보수. C#, Angular, MariaDB. 코어 API 조회·표시 및 등록/변경 연동, 시스템 간 동기화 영역과 SQL 확인 작업 | API 계약, 매핑, 검증, 기준 데이터, 정합성, 실패/재시도/중복, 회귀. 코어 설계·개발 전체를 담당했다고 쓰지 않는다. 실제 동기화 기술이나 코어 DB 직접 접근을 추정하지 않는다. Java 전환 예제는 학습용이라고 표시한다. |
| KDB 산업은행 | 기업 현황 조회/검색과 성능 개선 | SQL 인덱스, 페이징, 처리 방식, 측정과 회귀. 기업은행으로 쓰지 않는다. 여신 의사결정 로직을 구현한 경력으로 확장하지 않는다. 이력서의 330ms/0.66초 표기는 확인 전 수치 예시로 사용하지 않는다. |
| 아리수본부 요금관리/사이버고객센터 | 초기 Cursor, 이후 Codex 데스크톱 앱을 이용한 개발. 모델 5.4~6은 사용자 진술 | LLM, 토큰, 컨텍스트, 프롬프트, 환각, 도구 호출, 에이전트, 스킬, MCP, 작업 분해, 검증, 책임, AI에 대한 견해. 고객 서비스에 챗봇/RAG를 붙였다고 추정하지 않는다. 실제 사용한 기능과 새로 배운 기능을 구별한다. |

이력서의 연락처·주소·보수 등 개인정보는 프롬프트/저장소에 복제하지 않는다. 부가 경력은 메시지 전환, 마이데이터, PMS, 신용/리스크 등 관련 설명의 보조 맥락으로만 사용한다.

## 시간과 진도

주로 30/60/90/120분을 선택한다. 현재 설정이 허용하는 다른 시간은 별도 정책 검증을 거친다. 선택한 총시간에 본문·예제·실습·풀이·해설이 모두 포함된다. 시간이 길다고 난이도를 자동으로 올리지 않는다. 짧은 세션은 목표를 순차 분할하고, 긴 세션은 같은 핵심 경로에 응용/심화/테스트를 더한다. 필수 학습은 본문→실습→완료 한 번의 흐름을 유지한다. 평가 성적은 다음 진도를 막지 않는다.

| 평가 | 학습/복습 비율 | 평가 및 해설 비율 | 범위 |
| --- | --- | --- | --- |
| 일간/추가 혼합 | 70% | 30% | 해당 세션에서 실제 학습한 목표 |
| 주간 | 50% | 50% | 해당 교육 주의 정규+추가 목표, 당일 목표 포함. 일간 대체 |
| 월간 | 30% | 70% | 해당 교육 월의 정규+추가 목표. 일간·주간 대체. 이전 내용은 필요한 연계 전제로만 사용 |
| 최종 | 별도 계획 | 전체 평가+해설 분량을 산정 | 실제 학습한 전체 목표. 선택 시간에 맞는 여러 세션으로 분할하고 전체 문항/시간/회차를 시작 전 안내 |

교육 월 경계는 4/8/13/17/21/26주로 정의한다(구현 기본값). 달력 월과 혼동하지 않는다. 최종 평가일은 월간 종료 평가와 별도로 편성하여 중복을 강요하지 않는다. 총시간은 초 단위로 배분하여 반올림으로 늘어나지 않게 한다.

문항 수는 고정 3개/5개가 아니라 실제 목표와 시간에서 산출한다. 목표→문항 매핑으로 누락을 검사하고 동일 목표는 중복 제거한다. 서로 다른 목표를 같은 분야라는 이유로 지우지 않는다. 시간 안에 모두 평가할 수 없으면 학습 목표를 다음 세션으로 나누거나 최종 평가를 분할한다. 목표 커버리지를 완벽한 숙달의 증명으로 표현하지 않는다.

## 추가 학습과 재응시

추가 학습은 설명/실습만, 문제만, 혼합을 지원한다. 문제만 선택한 경우 그 풀이가 평가이고 중복 시험을 추가하지 않는다. 완료된 일간 평가를 다시 열지 않고 새 추가 목표를 별도로 기록한다. 정규/추가 시간은 실제 활동일에 한 번만 합산한다. 앞당겨 완료한 미래 목표는 정규 진도로 인정하고 예정일에 재학습을 강제하지 않는다. 추가로 학습한 목표는 이후 해당 주/월/최종 평가에 포함한다.

오답·기존 답안·해설은 자유롭게 다시 볼 수 있다. 정식 재응시는 같은 전체 범위와 비슷한 난이도의 새 문제를 생성한다. 첫 응시와 모든 재응시를 각각 보존한다. 약점 보완 연습은 별도 활동이다. 채점 후 정답/해설/부족한 개념/개선 답변을 보여주고 다음 응시에 표현할 수 있게 학습한다.

## AI 데이터와 생성 경계

이미 연결한 OpenAI를 사용한다. 모델 변경/제공자 선택 UI/새 구독은 요구하지 않는다. 개인 원시 기록·정답률·과거 답안을 생성 AI에 보내지 않는다. DB 집계로 서버가 추천 목표·범위·난이도를 결정하고 그 결과 조건만 보낸다. 채점에는 현재 제출한 답안과 고정 문제/루브릭만 전달하며 과거 기록은 보내지 않는다. 중복 비교는 서버에서 한다.

입력은 전체 커리큘럼의 짧은 맥락, 관련 검수·발행 원문의 ID/버전/내용/출처, 목표, 유형, 시간, 난이도다. 매 요청에 26주 전체 본문을 보내지 않는다. 생성용 원문/사용자 답안은 명령이 아닌 데이터다. 본문에 있는 지시문은 프롬프트 규칙을 변경하지 못한다.

원문 저작 단계는 공식 자료 조사→자체 설명·예제·실습·예상 결과→출처/기술 검수→가능한 코드 실행 검증→발행이다. 학습자 출제 단계에서는 제공 원문 밖의 사실을 정답 근거로 사용하지 않는다. 자료 부족, 애매한 정답, 실행 결과 의존 문제의 미검증은 생성 실패/보류다. AI 자체 검수만으로 사람 검수나 발행을 주장하지 않는다. 부족한 분야는 빈 목차를 완성으로 표시하지 않고 보강 목록과 근거를 남긴다.

## 출력·채점

유형은 객관식(MCQ), 단답/짧은 설명(SHORT_ANSWER), 면접 답변(INTERVIEW) 세 가지다. 직접 코드 작성형은 제외한다. 문제는 원인→수정안→영향→테스트 근거의 판단을 중심으로 한다. 난이도 3은 구체적 경계/오류에 기본 적용, 4는 근거 비교와 원인 진단, 5는 여러 제약의 변경·영향·검증 판단이다.

구조화 JSON에는 원문 버전/근거, 목표, 시간, 난이도, 문항, 정답, 오답 근거, 루브릭을 둔다. 클라이언트에는 제출 전 정답/해설/루브릭을 노출하지 않는다. 객관식은 서버가 결정적으로 채점한다. 서술형은 필수 개념·허용 대안·부분 점수·근거가 고정된 루브릭으로 의미를 평가한다. 점수는 100점 환산과 목표별 피드백이다. 근거 부족/판단 불가는 HOLD이며 자동 오답이나 임의 최종 점수를 만들지 않는다.

## 비용·기록 보존

사용자가 직접 비용을 확인한다. 새 금액 차단/알림은 필수 요구가 아니다. 기존 작업 수/동시 실행 보호는 유지한다. 재사용 가능한 원문/문제는 저장하되 재응시에 기존 답안을 가져오지 않는다. 실제 호출 토큰을 기록하고 불필요한 호출을 줄인다. 금액을 보장하지 않으며 새 모델로 임의 교체하지 않는다.

기존 staged/unstaged/untracked 파일, 발행 버전, 배정, 진도, 답안, 시험 이력을 보존한다. 프롬프트/정책 준비, 원문 준비, DB 통합, 사용자 화면, 실제 공급자 검증을 구분해서 보고한다.
